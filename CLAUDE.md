# GI chess-T1 — память проекта

Настольная игра «chess-T1» (вариант шахмат). Делается под Windows, две сборки. Этот файл читается каждую сессию — держать в актуальном состоянии.

---

## 1. АРХИТЕКТУРА — две базы, обязаны вести себя ОДИНАКОВО

| База | Технология | Цель | Где |
|---|---|---|---|
| **Основная** | Tauri 2 + React 19 + Zustand | Windows 10+, установщик `.msi` (NSIS, русский) | корень проекта |
| **Win7** | Electron 22 + React 19 + Zustand | Windows 7, установщик `.exe` (NSIS) | подпапка `electron-win7/` |

> ⚠️ **КРИТИЧНО: `electron-win7/` — это ФОРК фронтенда, а НЕ общий код.**
> У него собственные `src/engine/`, `src/components/`, `src/logic/`, `src/stores/`.
> Любую правку движка или UI нужно **ЗЕРКАЛИТЬ ВРУЧНУЮ** в `electron-win7/`.
> Сделал изменение в `src/` корня — сразу повтори его в `electron-win7/src/`.
> Поведение, тексты, иконки, правила — должны совпадать пиксель-в-пиксель и логика-в-логику.

Стек обеих баз: React 19, Zustand 5, html2canvas. Различается только оболочка (Tauri vs Electron) и версия Vite/тулинга.

## 2. КОМАНДЫ (точные, из package.json)

**Тесты** (только в корневой базе настроен vitest):
```
npx vitest run
```

**Сборка Tauri (.msi), из корня:**
```
npm run tauri build
```
(`tauri.conf.json` → `beforeBuildCommand: npm run build`, далее бандл `targets: all` → `.msi`/NSIS.)

**Сборка Electron (.exe), из `electron-win7/`:**
```
cd electron-win7
npm run dist
```
(= `vite build && electron-builder --win nsis` → `electron-win7/release/GI chess-T1 (Win7)_<version>_x64-setup.exe`.)

Dev-запуск: корень — `npm run tauri dev` (или `npm run dev` для веб-превью); win7 — `npm run dev:vite` / `npm run electron`.

## 4. ДВИЖОК ПРАВИЛ (`src/engine/`) — pure-логика, без UI

Точка входа — единственный источник истины, который дёргает GUI:

```ts
resolveMove(board, from, to, turn?) → {
  allowed,       // boolean
  reason,        // '' если разрешено, иначе текст вердикта (для §8)
  captureKind,   // 'none' | 'normal' | 'scout-exchange'
  nextBoard,     // доска после хода ('' = исходная при отказе)
  nextTurn       // чей ход дальше
}
```

`turn` задаёт строгую очередь (Партия); без него — свободный Анализ (цвет берётся у двигаемой фигуры).
`Board.tsx` вызывает `resolveMove` и применяет результат через `gameStore.commitMove`. Доску движок сам не мутирует — клонирует.

Файлы движка (`src/engine/`, экспорт через `index.ts`):
- `coords.ts` — координаты/клетки замка.
- `pieceInfo.ts` — типы фигур, королевские/некоролевские, сила.
- `movement.ts` — геометрия ходов по схеме каждой фигуры.
- `forceField.ts` — расчёт силового поля (проекция силы на клетку).
- `placement.ts` — правила расстановки.
- `validator.ts` — `validateMove` → вердикт (allowed/reason/capture) по §4–9.
- `resolveMove.ts` — чистое применение хода (см. выше).
- `index.ts` — реэкспорт.

Тесты движка: `src/__tests__/engine-*.test.ts` (book-validation, forcefield, move-flow, movement, movement-book, validator, verdict-validation).
**Зеркало:** `electron-win7/src/engine/` — те же 8 файлов, держать синхронно.

## 5. ПРАВИЛА chess-T1 — ИСТИНА из книг «Основы» и «Другие шахматы»

> Книга — источник истины. **Не «чинить» корректное поведение** — сначала свериться с книгой. Если тест/код расходится с книгой, прав код-по-книге, а ожидание правится под книгу.

**Сила (база: Кнехт = 1):**
| Фигура | Сила |
|---|---|
| Король | 1.5 |
| Коннет | 3 |
| Принц | 1.5 |
| Риттер | 2 |
| ВК | 1.5 |
| Кнехт | 1 |
| Разведчик | 0 (в защите) / ∞ (прямая атака на обычное поле) |

**Классы фигур:**
- Королевские: **Король, Коннет, Принц**.
- Некоролевские: **Кнехт, ВК, Риттер, Разведчик**.

**Клетки замка** (бел. `c1 d1 e1 f1` / чёрн. `c8 d8 e8 f8`):
- Попадать на них может **ТОЛЬКО королевская** фигура.
- **Исключение:** ВК на **ПУСТУЮ** клетку замка (это превращение).
- Некоролевские **проецируют силу** на замок, но **ходить и бить там не могут**.

**Ходы (схемы):**
- **Кнехт / ВК** — как пешка: 1 по прямой + ход вперёд в своей половине, без прыжка.
- **Риттер** — 1–2 по прямой, с прыжком на 2, без диагонали.
- **Принц** — 1 по прямой + 1–3 по диагонали, без прыжка.
- **Коннет** = Риттер + Принц (1–2 по прямой с прыжком на 2 + 1–3 по диагонали без прыжка).
- **Король** — 1 во все стороны.
- **Разведчик** — ход конём; на клетке замка = размен (снимаются обе фигуры).

**Взятие:**
- Только при **СТРОГОМ перевесе** силы на поле (равенство = запрет).
- Своя сила цели входит в её защиту.
- **Разведчик** — берёт безусловно на обычном поле; на замке — **размен** (обе снимаются).

**§6:** королевская фигура **не может выйти из своего замка**, если этим оставит замок королевской фигуре противника.

**Очередь хода:** и Партия, и Анализ-Игра **чередуют** ход (цвет первого хода настраивается). «Свобода» Анализа — это ветвление **Назад/Вперёд**, а **НЕ** ход вне очереди.

**НЕ Этап 1** (это Этапы 2–3): превращение (кроме базового ВК→замок?), шах, победа, ничья, Журнал. — не реализовывать в рамках Этапа 1.

## 6. СООБЩЕНИЯ (§8) — когда показывать тост

Временный тост показывать **ТОЛЬКО** когда ход по схеме фигуры **геометрически возможен**, но его блокирует **спец-правило**:
- нет перевеса силы для взятия;
- некоролевская фигура на клетку замка;
- §6 (нельзя оставить замок врагу).

На **геометрически невозможный** ход и на ход **на свою фигуру** — **молча отклонять, без тоста**.

- **Агент (Claude)** проверяет **только логику тестами** (`npx vitest run`). Агент **НЕ видит** отрендеренный UI.

- ⚠️ «Зелёные тесты» **≠** «проверено в окне». Не выдавать прохождение тестов за проверку интерфейса.
