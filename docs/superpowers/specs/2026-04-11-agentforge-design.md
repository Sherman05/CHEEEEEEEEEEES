# AgentForge — ИИ-агенты полного цикла разработки IT-продуктов

## Обзор

Платформа, в которой ИИ-агенты выполняют полный цикл разработки IT-продуктов: от идеи до деплоя. Разработчик описывает идею, PM-агент декомпозирует её, спавнит нужных агентов, координирует их работу и останавливается на контрольных точках для утверждения.

**Целевая аудитория:** сначала внутренний инструмент для своей команды, затем коммерческий SaaS.

**Уровень автономии:** человек-в-петле (контрольные точки), в будущем — полная автономия.

**Типы продуктов:** веб, десктоп, мобайл — всё.

---

## Архитектура

### Три слоя

1. **Веб-дашборд (фронтенд)** — React, реалтайм отображение работы агентов, чат с PM-агентом, утверждение контрольных точек, просмотр кода/дизайна.

2. **Оркестратор (бэкенд)** — управляет жизненным циклом агентов:
   - API-сервер (Node.js/TypeScript)
   - Шина событий (Redis Pub/Sub) — агенты общаются через неё
   - Менеджер состояний — хранит прогресс каждого проекта
   - Спавнер агентов — поднимает/останавливает агентов по команде PM

3. **Песочницы (execution layer)** — Docker-контейнеры:
   - Каждый проект = изолированный контейнер с git-репо
   - Кодеры пишут код внутри контейнера
   - Тестер запускает тесты там же
   - DevOps-агент билдит и деплоит из контейнера

### Поток данных

```
Пользователь (дашборд)
    ↓ задача
PM-агент (координатор)
    ↓ декомпозиция
Шина событий
    ↓ задачи агентам
[Продакт] [Архитектор] [Дизайн] [Кодер×N] [Тестер] [DevOps]
    ↓ результаты
PM-агент → контрольная точка → Пользователь утверждает
    ↓
Следующий этап
```

## Агенты

### PM-агент (мозг системы)
- Принимает задачу от пользователя
- Декомпозирует на подзадачи
- Решает каких агентов спавнить и сколько
- Следит за прогрессом, разруливает конфликты
- Останавливается на контрольных точках

### Продакт-агент
- Превращает идею в структурированную спеку
- Формирует user stories, acceptance criteria
- Выход: документ требований

### Архитектор-агент
- Выбирает стек технологий
- Проектирует структуру проекта, БД-схему, API
- Выход: архитектурный документ + scaffolding

### Дизайн-агент
- Генерирует UI-макеты (HTML/CSS прототипы)
- Подбирает цветовую схему, компоненты
- Выход: готовые компоненты интерфейса

### Кодер-агент (×N, динамическое масштабирование)
- PM спавнит столько, сколько нужно
- Каждый получает конкретную задачу
- Работают параллельно в разных git-ветках, потом мержат
- Выход: код в git

### Тестер-агент
- Пишет тесты по спеке
- Прогоняет после кодеров
- Если баг — задача обратно кодеру через шину
- Выход: тесты + отчёт

### Ревьюер-агент
- Проверяет код на качество, безопасность, соответствие спеке
- Выход: ревью с комментариями

### DevOps-агент
- Настраивает CI/CD
- Собирает билд
- Деплоит
- Выход: работающее приложение

### Контрольные точки
1. После спеки — "Так строим?"
2. После архитектуры — "Такой стек и структура ок?"
3. После дизайна — "Нравится UI?"
4. После кода + тестов — "Всё работает, деплоим?"

## Веб-дашборд

### Экраны

**1. Главная — список проектов**
- Карточки: название, статус, прогресс-бар, активные агенты
- Кнопка "Новый проект"

**2. Создание проекта**
- Чат с PM-агентом — описание идеи свободным текстом
- Прикрепление файлов (макеты, ТЗ, референсы)

**3. Проект — основной экран**
- Левая панель: этапы пайплайна (текущий подсвечен)
- Центр: рабочая область (документ/код/отчёт — зависит от этапа)
- Правая панель: реалтайм лог агентов
- Внизу: чат с PM-агентом

**4. Контрольная точка**
- Модальное окно с результатом этапа
- "Утвердить" / "Вернуть на доработку" + комментарий

**5. Мониторинг агентов**
- Список активных агентов, статус, потребление токенов
- Детальные логи каждого агента

## Технический стек

### Фронтенд
- React + TypeScript
- Tailwind CSS + shadcn/ui
- WebSocket — реалтайм
- Monaco Editor — просмотр/редактирование кода

### Бэкенд
- Node.js + TypeScript
- Express/Fastify — API
- Redis — шина событий (Pub/Sub) + кэш
- PostgreSQL — проекты, пользователи, история, логи
- Bull/BullMQ — очередь задач для агентов

### Агенты
- Claude API (Anthropic SDK)
- Каждый агент = воркер в очереди с нужным системным промтом
- Промты хранятся в БД — тюнинг без редеплоя

### Песочницы
- Docker — изолированный контейнер на проект
- Node.js/Python/Go + git + SDK в контейнере
- Результат в git-репо (GitHub/GitLab)

### Инфраструктура
- Docker Compose — разработка
- Kubernetes — продакшн
- S3 — артефакты

### Аутентификация
- JWT + refresh tokens
- Позже: OAuth (GitHub, Google)

## Система коммуникации агентов

### Формат событий
```json
{
  "projectId": "uuid",
  "agentType": "coder",
  "eventType": "task.completed",
  "payload": {},
  "timestamp": "ISO-8601"
}
```

### Типы событий
- `task.created` — PM создал задачу
- `task.progress` — агент отчитывается (стрим на дашборд)
- `task.completed` — агент завершил, результат в payload
- `task.failed` — ошибка, PM решает
- `checkpoint.reached` — этап завершён, ждём пользователя
- `review.requested` — кодер просит ревью
- `bug.found` — тестер нашёл баг

### Конфликты при параллельной работе
- Каждый кодер в своей git-ветке
- Автомерж в `dev` по завершении
- Конфликт → ревьюер-агент резолвит или эскалация PM

## Безопасность и изоляция

- Docker-контейнер на проект, без доступа к хосту
- API-ключи Claude в оркестраторе, агенты их не видят
- Лимиты CPU/RAM/диск на контейнер
- Полный аудит-лог всех действий агентов
- Ревьюер проверяет код на OWASP-уязвимости
- Мультитенантность для SaaS — полная изоляция данных клиентов

## Фазы реализации

### Фаза 1 — Ядро (MVP)
1. PM-агент + 1 кодер-агент (последовательно)
2. Простой веб-дашборд: создать проект → чат с PM → результат
3. Один тип — веб-приложение (React)
4. Без контейнеров — всё локально
5. Одна контрольная точка — утвердить спеку

### Фаза 2 — Параллелизм
6. Динамический спавн нескольких кодеров
7. Docker-песочницы
8. Тестер-агент + ревьюер-агент
9. Все контрольные точки
10. Реалтайм логи на дашборде

### Фаза 3 — Полный цикл
11. Продакт, архитектор, дизайн агенты
12. DevOps-агент + автодеплой
13. Десктоп/мобайл приложения
14. Kubernetes, масштабирование

### Фаза 4 — SaaS
15. Мультитенантность, биллинг
16. OAuth, командная работа
17. PM-агент общается с заказчиком
